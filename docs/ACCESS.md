# راهنمای سطوح دسترسی (نسخه‌ی ۲٫۵)

مدیر از منوی «سطوح دسترسی» (`/access`) برای هر معلم و معاون تعیین می‌کند چه کارهایی را بتواند انجام دهد.

## سه حالت برای هر کار
| حالت | معنی |
|---|---|
| پیش‌فرض نقش | همان که نقش (معلم/معاون) به‌طور معمول دارد |
| مجاز | حتی اگر نقش نداشته باشد، این فرد انجام دهد |
| ممنوع | حتی اگر نقش داشته باشد، این فرد انجام ندهد |

ترتیب ارزیابی: **تنظیم شخصی ← الگوی دسترسی ← پیش‌فرض نقش**. مدیر هرگز محدود نمی‌شود؛ دانش‌آموز و ولی هرگز قابلیت اداری نمی‌گیرند.

## نمونه‌ها
- *معلمی که بتواند رویداد به تقویم اضافه کند:* `/access` ← معلم ← بخش «تقویم و رویدادها» ← «مشاهده‌ی مدیریت رویدادها» و «افزودن رویداد» = مجاز.
- *معلم راهنما که ارزشیابی تعریف و نمره منتشر کند:* بخش «نمرات و ارزشیابی» ← «تعریف ارزشیابی»، «ثبت نمره» و «انتشار نمره» = مجاز (یا الگوی «معلم راهنما»).
- *معاونی که فقط ببیند و پرداخت ثبت نکند:* بخش «امور مالی» ← «ثبت پرداخت» = ممنوع (یا الگوی «معاون ناظر»).
- نمره‌ی قفل‌شده فقط با «اصلاح نمره‌ی قفل‌شده» و بازکردن قفل فقط با «بازکردن قفل نمرات» (قابل اعطا به معلم).
- «دامنه‌ی همه‌ی کلاس‌ها» لیست و ثبت نمره‌ی معلم را به همه‌ی دروس گسترش می‌دهد.

## الگوها
هر الگو مجموعه‌ای از مجاز/ممنوع است که به چند نفر نسبت داده می‌شود؛ تغییر الگو برای همه‌ی اعضا اعمال می‌شود. الگوی در حال استفاده حذف نمی‌شود. «کپی دسترسی» تنظیم یک فرد را به هم‌نقش دیگر کپی می‌کند.

## امنیت
- مجوزهای ⚠ (حذف، پرداخت، رمز، پشتیبان و …) فقط با رمز مدیر ذخیره می‌شوند.
- هر تغییر (`perm_change`) و هر ردّ دسترسی (`denied`) در «گزارش فعالیت‌ها» ثبت می‌شود و کاربر اعلان می‌گیرد.
- منو، دکمه و صفحه‌ها فقط به‌اندازه‌ی مجوز دیده می‌شوند؛ سرور هر درخواست را جداگانه بررسی می‌کند، پس مخفی‌بودن دکمه تنها تکیه‌گاه نیست.
- برای افزودن قابلیت تازه در کد: `src/lib/caps.js` (فهرست و نگاشت مسیر) و اجرای `node test/v25.access.test.js`؛ مسیر نوشتنیِ بی‌مالک تست را شکست می‌دهد.
