## ۱. پیش‌نیازها و آمادگی

### ۱-۱. هاست باید چه داشته باشد؟
- **Setup Node.js App** در cPanel (نام دیگر: Node.js Selector / CloudLinux). اگر در cPanel خود این گزینه را نمی‌بینید، از پشتیبانی هاست بخواهید فعالش کند. بدون آن نصب ممکن نیست.
- **Node.js نسخه ۱۸ یا بالاتر** (۲۰ یا ۲۲ پیشنهاد می‌شود؛ هر دو آزمون شده‌اند).
- **MySQL / MariaDB** (پیشنهاد اصلی برای هاست اشتراکی).
  - SQLite هم پشتیبانی می‌شود، ولی نیاز به کامپایل `better-sqlite3` دارد که روی بسیاری از هاست‌ها ممکن نیست. اگر نصب نشد مشکلی نیست؛ MySQL را انتخاب کنید.
- حداقل **۲۵۶ مگابایت** حافظه برای برنامه (۵۱۲ بهتر است).
- **SSL (https)** برای دامنه — در cPanel بخش **SSL/TLS Status** ← **Run AutoSSL**.

### ۱-۲. چه چیزی را آپلود می‌کنید؟
کل پوشه‌ی پروژه **به‌جز** این‌ها:
- `node_modules` (روی خود هاست نصب می‌شود)
- `.git`
- پوشه‌ی `data` (اگر قبلاً روی کامپیوتر خودتان برنامه را اجرا کرده‌اید؛ وگرنه فقط یک `data/.gitkeep` دارد و مشکلی ندارد)

فونت وزیرمتن و آیکن‌ها داخل خود پروژه هستند (`public/fonts`، `src/icons`)؛ نیازی به اینترنت یا ساخت جداگانه نیست.

**راه ساده برای گرفتن فایل‌ها:**
1. از GitHub، شاخه‌ی مورد نظر را **Download ZIP** کنید (Code ← Download ZIP).
   - نسخه‌ی ۲٫۱٫۰ روی شاخه‌ی `arena/01a0f6f5-mad3` است و تا زمانی که PR شماره‌ی ۱ را merge نکرده‌اید روی `main` نیست.
2. یا روی کامپیوتر خودتان (اگر پروژه را clone کرده‌اید):
   ```bash
   zip -r school.zip . -x "node_modules/*" ".git/*" "data/*"
   ```

### ۱-۳. آماده‌کردن اطلاعات
پیش از شروع این‌ها را کنار دستتان داشته باشید:
- نام دامنه یا زیردامنه (مثلاً `school.example.com`) — یا مسیر زیرپوشه (مثلاً `example.com/school`)
- نام مدرسه
- نام کاربری و رمز مدیر (رمز حداقل ۸ نویسه؛ آن را جایی امن بنویسید)
- مشخصات پایگاه داده (در مرحله‌ی بعد می‌سازید)

> **دامنه/زیردامنه بهتر از زیرپوشه است.** سامانه از هر دو پشتیبانی می‌کند (با زیرمسیر `/school` آزمون شده)، ولی زیردامنه ساده‌تر و کم‌خطاتر است.

## ۲. نصب واقعی سامانه

### مرحله ۱ — آپلود و استخراج فایل‌ها
1. وارد cPanel شوید ← **File Manager**.
2. به پوشه‌ی خانگی (`/home/USER`) بروید — **نه** داخل `public_html`.
   - اپلیکیشن Node نباید داخل `public_html` باشد، تا فایل‌های برنامه و پوشه‌ی `data` (شامل تنظیمات دیتابیس) مستقیم از وب در دسترس نباشند.
3. پوشه‌ای بسازید، مثلاً `school` (مسیر نهایی: `/home/USER/school`).
4. وارد آن پوشه شوید ← **Upload** ← فایل ZIP را آپلود کنید ← روی فایل راست‌کلیک ← **Extract**.
5. **نکته‌ی مهم:** اگر ZIP گیت‌هاب را آپلود کردید، همه‌چیز داخل یک پوشه‌ی تو در تو (مثل `mad3-arena-.../`) استخراج می‌شود. محتویات آن را به پوشه‌ی `school` منتقل کنید (Select All ← Move) تا `app.js` و `package.json` **مستقیماً** داخل `/home/USER/school` باشند.
6. بررسی کنید در `/home/USER/school` این موارد هست: `app.js`، `package.json`، پوشه‌های `src`، `views`، `public`، `scripts`، `data`.
7. اگر پوشه‌ی `data` نیست، بسازید (Create New Folder). مجوزش باید **755** باشد (راست‌کلیک ← Change Permissions).

### مرحله ۲ — ساخت پایگاه داده MySQL
1. cPanel ← **MySQL® Databases**.
2. **Create New Database**: نامی مثل `school` بدهید. cPanel پیشوند حساب را اضافه می‌کند، مثلاً `cpuser_school`. این نام کامل را یادداشت کنید.
3. **MySQL Users ← Add New User**: نام کاربری (مثلاً `sch`، که می‌شود `cpuser_sch`) و یک **رمز قوی** (از Password Generator استفاده کنید). نام کامل و رمز را یادداشت کنید.
4. **Add User To Database**: کاربر و پایگاه داده را انتخاب کنید ← **Add** ← تیک **ALL PRIVILEGES** ← **Make Changes**.
5. پایگاه داده باید **خالی** باشد. (ویزارد روی پایگاه داده‌ی غیرخالی نصب نمی‌کند.)

اطلاعاتی که در ویزارد لازم دارید:

| فیلد | مقدار |
|---|---|
| میزبان (Host) | `localhost` |
| پورت | `3306` |
| نام پایگاه داده | `cpuser_school` (نام کامل با پیشوند) |
| نام کاربری | `cpuser_sch` (نام کامل با پیشوند) |
| رمز | رمزی که ساختید |

### مرحله ۳ — ساخت اپلیکیشن Node.js
1. cPanel ← **Setup Node.js App** ← **Create Application**.
2. فرم را این‌طور پر کنید:

| فیلد | مقدار |
|---|---|
| Node.js version | `20` (یا ۲۲، یا بالاتر از ۱۸) |
| Application mode | `Production` |
| Application root | `school` (مسیر نسبی پوشه‌ی مرحله ۱) |
| Application URL | دامنه یا زیردامنه‌ی خودتان (برای زیرپوشه: دامنه و مسیر، مثل `example.com/school`) |
| Application startup file | `app.js` |

3. **Create** را بزنید.
4. در صفحه‌ی اپلیکیشن، دکمه‌ی **Run NPM Install** را بزنید و صبر کنید تا پایان یابد (چند دقیقه).
   - هشدار درباره‌ی `better-sqlite3` یا ساخت (build) آن **عادی است** و نصب را متوقف نمی‌کند (وابستگی اختیاری است). MySQL را در ویزارد انتخاب می‌کنید.
   - اگر نصب بر اثر محدودیت منابع هاست قطع شد، یک بار دیگر بزنید. اگر باز هم نشد به [عیب‌یابی](#۹-عیب‌یابی) بروید.
5. (اختیاری) در بخش **Environment variables** (دکمه‌ی Add Variable) متغیرها را اضافه کنید. همه اختیاری‌اند:

| متغیر | کاربرد |
|---|---|
| `SESSION_SECRET` | کلید نشست؛ اگر نگذارید ویزارد کلید تصادفی می‌سازد (پیشنهاد: نگذارید) |
| `BASE_PATH` | فقط اگر در زیرپوشه نصب می‌کنید و تشخیص خودکار کار نکرد، مثلاً `/school` |
| `SECURE_COOKIES` | `true` برای اجبار کوکی امن (روی https معمولاً خودکار فعال می‌شود) |
| `SCHOOL_DATA_DIR` | مسیر دلخواه برای پوشه‌ی data (مثلاً `/home/USER/school-data`) |
| `DB_CLIENT`, `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` | تنظیم دیتابیس از محیط (اولویت بالاتر از ویزارد) |

6. **Restart** را بزنید (یا ابتدا **Save** و سپس **Restart**).

### مرحله ۴ — ویزارد نصب
> ⚠️ **همین لحظه ویزارد را کامل کنید.** تا پایان نصب، هر کسی که نشانی سایت را باز کند می‌تواند ویزارد را ببیند.

1. نشانی اپلیکیشن را در مرورگر باز کنید (مثلاً `https://school.example.com`). ویزارد نصب با شش گام نمایش داده می‌شود:
2. **خوش‌آمدگویی / پیش‌نیازها:** فهرست بررسی‌ها را ببینید. موارد اجباری باید سبز باشند:
   - نسخه‌ی Node.js ≥ ۱۸
   - دسترسی نوشتن در پوشه‌ی `data` ← اگر قرمز بود، مجوز پوشه را ۷۵۵ (یا ۷۷۵) کنید.
   - درایور SQLite و حافظه‌ی آزاد «اختیاری» هستند و قرمزبودنشان مانع نصب نیست.
3. **پایگاه داده:** `MySQL` را انتخاب کنید، مشخصات جدول بالا را وارد کنید، **آزمایش اتصال** را بزنید. تا «اتصال موفق» نیاید ادامه ندهید.
4. **مدرسه:** نام مدرسه و اطلاعات تماس.
5. **مدیر:** نام کاربری، نام کامل و **رمز (حداقل ۸ نویسه)**. این همان حسابی است که با آن همه‌چیز را مدیریت می‌کنید.
6. **ماژول‌ها:** هر ماژولی را که لازم ندارید خاموش کنید (بعداً هم از منوی «ماژول‌ها» قابل تغییر است).
   - تیک **«نصب داده‌های نمونه (دمو)» را بردارید** (برای نصب واقعی). به‌صورت پیش‌فرض این تیک **روشن** است!
7. **نصب:** دکمه‌ی شروع نصب را بزنید و صبر کنید تا صفحه‌ی «نصب با موفقیت انجام شد» بیاید.
8. **ورود به سامانه** را بزنید و با نام کاربری و رمزی که در گام ۵ ساختید وارد شوید.

حالا بروید به [بخش ۶: کارهای لازم پس از نصب](#۶-کارهای-لازم-پس-از-نصب).

## ۳. نصب نسخه‌ی دمو

دمو یعنی سامانه با **داده‌ی نمونه**: ۶ کلاس، ۷۲ دانش‌آموز، معلم‌ها، برنامه‌ی هفتگی، حضور و غیاب، نمرات، تیکت، مالی، اعلانات و حساب‌های ورود آماده — برای آشنایی با امکانات یا نمایش به دیگران.

دو راه دارید. **راه الف (ویزارد) ساده‌تر است.**

### راه الف — با ویزارد (پیشنهادی)
مراحل **۱ تا ۳ بخش ۲** را دقیقاً مثل نصب واقعی انجام دهید (آپلود، پایگاه داده، ساخت اپلیکیشن). سپس در مرحله‌ی ویزارد:
1. گام‌ها را تا **ماژول‌ها** بروید (برای دمو بهتر است همه‌ی ماژول‌ها روشن بمانند تا همه‌چیز را ببینید).
2. تیک **«نصب داده‌های نمونه (دمو)»** را **روشن** نگه دارید (پیش‌فرض روشن است).
3. نصب را بزنید.
4. در صفحه‌ی پایان، حساب‌های دمو نمایش داده می‌شود و صفحه‌ی ورود هم کادر «حساب‌های نمونه» دارد.

### راه ب — با خط فرمان (بدون ویزارد)
مناسب وقتی که ویزارد در مرورگر مشکل دارد یا می‌خواهید دمو را سریع و تکرارپذیر بسازید.
1. مرحله‌های ۱ تا ۳ از بخش ۲ را انجام دهید ولی **ویزارد را باز نکنید**.
2. در **Setup Node.js App** بالای صفحه‌ی اپلیکیشن، دستور **«Enter to the virtual environment»** نوشته شده است (شبیه `source /home/USER/nodevenv/school/20/bin/activate && cd /home/USER/school`). آن را کپی کنید.
3. cPanel ← **Terminal** را باز کنید (اگر ندارید از SSH استفاده کنید)، دستور بالا را اجرا کنید.
4. حالا با متغیرهای دیتابیس، دمو را نصب کنید (همه را در یک خط بنویسید و مقدارها را عوض کنید):
   ```bash
   DB_CLIENT=mysql DB_HOST=localhost DB_PORT=3306 DB_NAME=cpuser_school DB_USER=cpuser_sch DB_PASSWORD='رمز-دیتابیس' \
   ADMIN_USER=admin ADMIN_PASSWORD='یک-رمز-قوی-۸+-نویسه' SCHOOL_NAME='مدرسه نمونه' \
   SECURE_COOKIES=true BASE_PATH='' \
   node scripts/install-demo.js
   ```
   - اگر در **زیرپوشه** نصب کرده‌اید: `BASE_PATH='/school'`.
   - اگر `ADMIN_PASSWORD` ندهید، رمز پیش‌فرض عمومی `Admin#12345` می‌شود (فقط برای دمویی که بیرون باز نیست).
   - اگر SQLite دارید: متغیرهای `DB_*` را ننویسید.
5. پایان موفق چنین پیامی دارد: `نصب انجام شد. ورود مدیر: ...`
6. در Setup Node.js App دکمه‌ی **Restart** را بزنید و نشانی سایت را باز کنید.

> برای اجرای دوباره‌ی دستور، پایگاه داده باید خالی باشد، یا اول [بازنشانی](#۴-رفتن-از-دمو-به-نصب-واقعی) بزنید.

### حساب‌های ورود در دمو

| نقش | نام کاربری | رمز |
|---|---|---|
| مدیر کل | همان که در نصب انتخاب کردید (با CLI پیش‌فرض: `admin`) | رمز نصب (با CLI پیش‌فرض: `Admin#12345`) |
| معاون | `deputy` | `deputy123` |
| معلم (راهنمای هفتم الف) | `t.ahmadi` | `teacher123` |
| معلم (غیر راهنما، چند کلاس) | `a.taheri` | `teacher123` |
| دانش‌آموز | `14050001` | `student123` |
| ولی (پدر دانش‌آموز بالا) | شماره‌ی همراه پدر (در کادر حساب‌های نمونه‌ی صفحه‌ی ورود نوشته شده) | `parent123` |

### چه چیزهایی را در دمو امتحان کنید؟
- **مدیر:** داشبورد و کارهای امروز ← «دانش‌آموزان» و پرونده‌ی کامل ← «برنامه‌ی هفتگی» و «ساعت زنگ‌ها» ← «تعطیلات» ← «نمرات» و قفل نمره ← «تیکت‌ها» ← «مالی» ← «گزارش‌ها» ← «پایان سال تحصیلی» ← «پشتیبان‌گیری» ← «تنظیمات» (۱۲ تب) ← «ماژول‌ها».
- **معلم:** ثبت حضور و غیاب ← ثبت نمره ← تکلیف ← تیکت به مدیر.
- **دانش‌آموز/ولی:** پنل شخصی، غیبت‌ها، نمرات، ثبت تیکت غیبت همراه با آپلود گواهی (تصویر تا ۵ مگابایت).
- **همه:** جستجوی بالای صفحه، منوی کناری آکاردئونی، حالت تیره.

### ⚠️ هشدار امنیتی دمو
دمو حساب‌هایی با **رمزهای عمومی** دارد (در همین راهنما نوشته شده). و در نصب دمو دو گزینه روشن می‌شود:
- **نمایش حساب‌های دمو در صفحه‌ی ورود** (تب «ظاهر»)
- **نمایش کد تأیید پیامکی روی صفحه** در حالت آزمایشی (تب «پیامک (ippanel)»)

پس **دمو را روی سایتی که اطلاعات واقعی دارد یا برای عموم باز است به‌عنوان سامانه‌ی واقعی استفاده نکنید.** اگر دمو را روی یک دامنه‌ی عمومی گذاشته‌اید، فقط داده‌ی نمونه در آن باشد و رمز **مدیر کل** را قوی بگذارید.

## ۴. رفتن از دمو به نصب واقعی

دمو و داده‌ی واقعی را **نباید قاطی کرد.** سامانه دکمه‌ی «حذف فقط داده‌ی نمونه» ندارد؛ راه درست، نصب تازه روی پایگاه داده‌ی خالی است.

1. اگر داده‌ی واقعی در آن وارد کرده‌اید، **ابتدا پشتیبان بگیرید** (منوی «پشتیبان‌گیری»).
2. در Terminal، محیط مجازی اپلیکیشن را فعال کنید (مرحله‌ی ۲ راه ب بخش ۳) و اجرا کنید:
   ```bash
   node scripts/reset-install.js --yes --uploads --backups
   ```
   این دستور: جدول‌های MySQL را حذف می‌کند (یا فایل SQLite را)، فایل‌های `config.json`، `installed.lock` و `install-state.json` را پاک می‌کند، و با `--uploads` فایل‌های بارگذاری‌شده و با `--backups` پشتیبان‌های روی سرور را هم پاک می‌کند. **بازگشت‌پذیر نیست.**
3. در Setup Node.js App دکمه‌ی **Restart** را بزنید.
4. نشانی سایت را باز کنید؛ ویزارد دوباره می‌آید. این بار تیک **دمو را بردارید** ([بخش ۲، مرحله ۴](#مرحله-۴--ویزارد-نصب)).

**راه بدون Terminal:** در phpMyAdmin همه‌ی جدول‌ها را حذف کنید (Select All ← Drop)، در File Manager از پوشه‌ی `data` فایل‌های `config.json`، `installed.lock` و `install-state.json` را پاک کنید (و در صورت نیاز محتوای `data/uploads`)، سپس Restart.

> راه سوم: یک پایگاه داده‌ی جدید و یک اپلیکیشن جدید بسازید و دمو را همان‌طور که هست روی جای قبلی نگه دارید.

## ۵. سایت دموی عمومی با بازنشانی خودکار

اگر می‌خواهید سایتی برای نمایش به مدرسه‌ها/مشتری‌ها داشته باشید که هر شب به حالت اول برگردد:

1. یک **زیردامنه‌ی جدا** بسازید (مثلاً `demo.example.com`)، یک **پایگاه داده‌ی جدا** و یک **اپلیکیشن Node.js جدا** (همان مراحل بخش ۲ ولی با نام `demo`).
2. دمو را با [راه ب](#راه-ب--با-خط-فرمان-بدون-ویزارد) نصب کنید. رمز مدیر را قوی بگذارید.
3. cPanel ← **Cron Jobs** ← **Add New Cron Job**. زمان: هر شب ساعت ۳ (`0 3 * * *`). دستور:
   ```bash
   cd /home/USER/demo && /home/USER/nodevenv/demo/20/bin/node scripts/reset-install.js --yes --uploads --reinstall-demo && mkdir -p tmp && touch tmp/restart.txt
   ```
   (مسیر `nodevenv/demo/20` را از دستور «Enter to the virtual environment» همان اپلیکیشن بردارید؛ عدد ۲۰ نسخه‌ی Node است.)
   - برای اینکه رمز مدیر همان رمز دلخواه شما بماند، متغیرها را جلوی دستور بگذارید: `ADMIN_USER=admin ADMIN_PASSWORD='...' SECURE_COOKIES=true` (`SECURE_COOKIES` هم همان‌جا).
4. این روش برای **MySQL** است. برای SQLite توصیه نمی‌شود (فایل دیتابیس زیر پای برنامه‌ی در حال اجرا حذف می‌شود).
5. با هر بازنشانی همه‌ی کاربران از سامانه خارج می‌شوند و تغییراتشان پاک می‌شود — برای دمو همین مطلوب است.

## ۶. کارهای لازم پس از نصب

### ۶-۱. امنیت (برای نصب واقعی، همین امروز)
- [ ] سایت روی **https** باشد (AutoSSL) و در cPanel ← **Domains** گزینه‌ی **Force HTTPS Redirect** روشن باشد.
- [ ] رمز مدیر قوی است. در «تنظیمات ← امنیت» حداقل طول رمز و مدت نشست را ببینید.
- [ ] اگر دمو نصب کرده‌اید: «تنظیمات ← ظاهر» ← **نمایش حساب‌های دمو در صفحه ورود** را خاموش کنید، و «تنظیمات ← پیامک (ippanel)» ← **نمایش کد روی صفحه در حالت آزمایشی** را خاموش کنید. بهتر: [نصب تازه](#۴-رفتن-از-دمو-به-نصب-واقعی).
- [ ] پوشه‌ی اپلیکیشن بیرون از `public_html` است.
- [ ] مجوز پوشه‌ی `data` برابر ۷۵۵ است (۷۷۷ نباشد).

### ۶-۲. تنظیمات اولیه مدرسه
وارد **تنظیمات** شوید (۱۲ تب؛ ذخیره‌ی هر تب مستقل است):
1. **اطلاعات مدرسه:** نام، مدیر، تلفن، نشانی. لوگو را در تب «ظاهر» بارگذاری کنید.
2. **آموزشی:** مقیاس نمره، نمره‌ی قبولی، تعداد نوبت‌ها، **روزهای هفته‌ی مدرسه** و (اختیاری) قفل خودکار نمرات.
3. **ساعت زنگ‌ها** (از لینک میان‌بر در تب آموزشی): زنگ‌های هر پایه و روز (مثلاً چهارشنبه ۶ زنگ).
4. **تعطیلات:** در «تعطیلات» دکمه‌ی افزودن تعطیلات رسمی ثابت سال جاری را بزنید؛ تعطیلی‌های قمری و تعطیلی‌های خاص مدرسه را **دستی** اضافه کنید.
5. **سال تحصیلی**، **دروس**، **معلم‌ها**، **کلاس‌ها** (هر کلاس یک معلم راهنما)، **دانش‌آموزان** (هرکدام پرونده‌ی کامل و حساب کاربری) را به همین ترتیب وارد کنید.
6. **ماژول‌ها:** هر امکانی که لازم ندارید خاموش کنید.

### ۶-۳. Cron (کارهای خودکار) — مهم
بدون cron این‌ها خودکار انجام نمی‌شوند: پشتیبان‌گیری روزانه، قفل خودکار نمرات، یادآوری اقساط، بستن خودکار تیکت‌ها، پاک‌سازی نشست‌ها.

1. در سامانه: **تنظیمات ← تب «نگهداری و پشتیبان»**. نشانی cron و دستورهای آماده (curl/wget) آنجا نمایش داده می‌شود و دکمه‌ی «کپی» دارد.
2. cPanel ← **Cron Jobs** ← **Add New Cron Job**:
   - **Common Settings:** Once Per Fifteen Minutes (`*/15 * * * *`)
   - **Command** (نشانی و توکن را از صفحه‌ی تنظیمات کپی کنید):
     ```bash
     curl -fsS "https://school.example.com/cron?token=TOKEN" >/dev/null 2>&1
     ```
     (در زیرپوشه: `https://example.com/school/cron?token=TOKEN`)
3. ذخیره کنید. بعد از ۱۵ دقیقه در همان تب «آخرین اجرا» را ببینید.
4. نکات: بیش از یک بار در هر ۶۰ ثانیه جواب `429` می‌گیرد (طبیعی است). توکن غلط `403` می‌دهد. اگر توکن لو رفت، «بازسازی توکن» را بزنید و دستور cron را عوض کنید. توکن را جایی منتشر نکنید.

### ۶-۴. پشتیبان‌گیری خودکار
- در همان تب: **پشتیبان‌گیری خودکار روزانه** را روشن کنید و تعداد نسخه‌های نگهداری‌شده را تعیین کنید (پیش‌فرض ۷). با cron بالا هر شب اجرا می‌شود.
- پشتیبان‌ها در `data/backups` ذخیره می‌شوند — روی **همان سرور**. گاه‌گاهی (مثلاً هفتگی) یک نسخه را از منوی «پشتیبان‌گیری» **دانلود** و جای دیگری نگه دارید.
- پوشه‌ی `data/uploads` (عکس‌ها، مدارک، گواهی‌ها) داخل پشتیبان JSON نیست؛ جداگانه کپی کنید.
- با **Backup Wizard** خود cPanel هم می‌توانید از پایگاه داده و پوشه‌ی خانگی پشتیبان بگیرید.

### ۶-۵. پیامک (اختیاری، IPPanel)
در **تنظیمات ← تب «پیامک (ippanel)»**:
1. **فعال‌سازی ارسال پیامک** را روشن کنید و **سرویس‌دهنده** را روی **ippanel** بگذارید (حالت پیش‌فرض «آزمایشی» فقط در گزارش ثبت می‌کند و پیامکی نمی‌فرستد). **کلید API** (Access Key پنل ippanel) و **شماره ارسال‌کننده** (مثل `+983000505`) را وارد کنید. نشانی پایه‌ی پیش‌فرض `https://edge.ippanel.com/v1` را عوض نکنید.
2. «پیامک آزمایشی» را از «مرکز پیامک» بفرستید و وضعیت را در گزارش ببینید.
3. **ورود/فراموشی رمز با کد پیامکی:** در پنل ippanel یک **الگو (Pattern)** بسازید که یک متغیر دارد (مثلاً `code`). گزینه‌ی «کد یکبارمصرف پیامکی» را روشن کنید، **کد الگو** را در «کد الگوی (Pattern) ippanel برای کد تأیید» و نام متغیر را در «نام متغیر کد در الگو» (پیش‌فرض `code`) بنویسید. راهنمای کامل در همان تب است.
4. پیامک واقعی فقط وقتی ارسال می‌شود که کلید API معتبر باشد؛ بدون آن فقط در لاگ ثبت می‌شود.

## ۷. به‌روزرسانی

1. **پشتیبان بگیرید** (منوی «پشتیبان‌گیری») و `data/uploads` را کپی کنید.
2. (اختیاری ولی خوب) «تنظیمات ← نگهداری و پشتیبان» ← **حالت تعمیر** را روشن کنید تا کاربران عادی پیام تعمیر ببینند و فقط مدیر کل کار کند.
3. فایل‌های نسخه‌ی جدید را روی قبلی کپی کنید. **پوشه‌ی `data` را حذف یا جایگزین نکنید** (ZIP جدید را بدون `data` استخراج کنید).
4. Setup Node.js App ← **Run NPM Install** ← **Restart**.
5. جدول‌ها و ستون‌های جدید هنگام راه‌اندازی **خودکار** ساخته می‌شوند (نیازی به کار دستی نیست).
6. وارد شوید، چند صفحه‌ی مهم را باز کنید، سپس حالت تعمیر را خاموش کنید.

## ۸. دستورهای مفید (Terminal)
ابتدا محیط مجازی را فعال کنید (دستور «Enter to the virtual environment» در صفحه‌ی اپلیکیشن).

| کار | دستور |
|---|---|
| بازنشانی رمز یک کاربر (مثلاً مدیر فراموش‌کرده) | `node scripts/reset-admin.js نام‌کاربری رمز-جدید-حداقل-۸-نویسه` |
| پاک‌کردن نصب (بازگشت به ویزارد) | `node scripts/reset-install.js --yes [--uploads] [--backups]` |
| بازنشانی و نصب دوباره‌ی دمو | `node scripts/reset-install.js --yes --uploads --reinstall-demo` |
| نصب دمو بدون ویزارد | `node scripts/install-demo.js` (با متغیرهای `DB_*` و `ADMIN_*`، بخش ۳) |
| بررسی سلامت | باز کردن `/healthz` در مرورگر (باید `{"ok":true,...}` بدهد) |
| ری‌استارت بدون پنل | `mkdir -p tmp && touch tmp/restart.txt` در پوشه‌ی اپلیکیشن |

## ۹. عیب‌یابی

| نشانه | علت و راه‌حل |
|---|---|
| صفحه‌ی خطای Passenger / ۵۰۳ / «Incomplete response» | لاگ را ببینید: فایل `stderr.log` در پوشه‌ی اپلیکیشن یا cPanel ← **Errors** (و بخش لاگ‌ها در Setup Node.js App). معمولاً: **Run NPM Install** انجام نشده، یا نسخه‌ی Node پایین‌تر از ۱۸ است، یا Startup file برابر `app.js` نیست. |
| `Cannot find module ...` | NPM Install ناقام مانده؛ دوباره **Run NPM Install** بزنید، سپس Restart. مطمئن شوید `package.json` مستقیماً در Application root است (نه در یک پوشه‌ی تو در تو). |
| NPM Install وسط کار قطع می‌شود | محدودیت CPU/حافظه (LVE) هاست. چند دقیقه صبر و دوباره تلاش کنید؛ یا از پشتیبانی هاست محدودیت را بالا ببرید. |
| `better-sqlite3` خطای build می‌دهد | عادی و بی‌خطر است (اختیاری). در ویزارد MySQL را انتخاب کنید. |
| ویزارد: «دسترسی نوشتن ندارد» | مجوز پوشه‌ی `data` را به `755` (یا `775`) بدهید. مطمئن شوید مالک پوشه کاربر cPanel است. |
| ویزارد: «آزمایش اتصال» ناموفق | نام پایگاه داده و کاربر باید **با پیشوند cPanel** باشد (`cpuser_...`)؛ کاربر باید به پایگاه داده با ALL PRIVILEGES اضافه شده باشد؛ میزبان `localhost`. |
| ویزارد: «پایگاه داده خالی نیست» | یک پایگاه داده‌ی خالی بسازید یا جدول‌ها را در phpMyAdmin حذف کنید (یا `reset-install.js`). |
| سایت بدون استایل/فونت (در زیرپوشه) | `BASE_PATH` را برابر مسیر Application URL بگذارید (مثل `/school`) و Restart. |
| بعد از ورود دوباره به صفحه‌ی ورود می‌روید | روی http هستید ولی `SECURE_COOKIES=true` است (یا ساعت سرور اشتباه است). متغیر را حذف کنید یا SSL را فعال کنید. |
| «حالت تعمیر» روشن مانده و وارد نمی‌شوم | با حساب **مدیر کل** وارد شوید (او مستثنی است) و در تنظیمات خاموشش کنید. |
| cron جواب ۴۰۳ می‌دهد | توکن اشتباه یا قدیمی است؛ دستور را از تنظیمات دوباره کپی کنید. |
| cron جواب ۴۲۹ می‌دهد | کمتر از ۶۰ ثانیه از اجرای قبلی گذشته؛ زمان‌بندی را به ۱۵ دقیقه بگذارید. |
| آپلود گواهی رد می‌شود | فقط JPG/PNG/WebP تا ۵ مگابایت و فایل واقعاً تصویر باشد. |
| پیامک نمی‌رود | کلید API، شماره‌ی ارسال‌کننده و اعتبار پنل را بررسی کنید؛ وضعیت و پیام خطا در «مرکز پیامک» ثبت می‌شود. |
| رمز مدیر را فراموش کرده‌ام | مدیر دیگری رمز را از «کاربران» بازنشانی کند، یا `node scripts/reset-admin.js` (بخش ۸). |
| بعد از به‌روزرسانی خطا می‌دهد | NPM Install را دوباره بزنید و Restart؛ در صورت لزوم از پشتیبان بازیابی کنید (منوی «پشتیبان‌گیری»، تأیید دوگانه). |

اگر مشکل حل نشد، **متن آخرین بخش لاگ** (`stderr.log`) را نگه دارید؛ دقیق‌ترین سرنخ همان است.
